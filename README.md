# Rounded Desktop & Explorer Selection

A Windhawk mod for rounded, translucent selection on the Windows desktop and
in File Explorer. File hover/selection, column-header hover and the view buttons
in Explorer's lower-right corner share the configurable color and opacity.

**Version 0.2.6 · experimental · Windows 11 x64**

[Português](docs/README.pt-BR.md) · [Configuration](docs/configuration.md) ·
[Development](docs/development.md) · [Changelog](CHANGELOG.md)

![Generated preview of the default selection style](docs/preview.png)

The preview is generated by renderer tests. Defaults: #E81123, 20% fill opacity,
80% border opacity, 8 DIP selection radius, and 1 DIP border. Headers and view
buttons use a smaller 4 DIP radius. The mod ID remains
`rounded-desktop-selection` so existing installations can be upgraded.

## Features and scope

- Rounded desktop drag-selection rectangle.
- The same translucent selector in Explorer's DirectUI file view.
- Rounded file hover and selected-item backgrounds.
- Rounded column-header hover/pressed states, retaining native sort arrows.
- Explorer view buttons in the lower-right corner use the same colors.
- Independent switches for Explorer highlights and Explorer marquee.
- Navigation-tree styling, file text/icons, and native selection hit testing are preserved.

The compositor uses premultiplied alpha to preserve translucent Explorer panes.
Native rectangular focus borders are suppressed where the mod provides its
rounded outline; geometry adjustments made by DirectUI's border pass are retained.

## Compatibility

Validated initially on Windows 11 x64 build 26300, comctl32 6.0.26100.9278,
with Windhawk 1.7.3. ARM64, Windows 10, other builds and mixed-DPI configurations
have not been validated.

Desktop geometry uses private symbols and a recognized instruction pattern.
Explorer marquee uses separate symbols and DirectUI exports. Capabilities are
resolved independently and unsupported paths retain native painting.

Avoid combining this mod with another mod that replaces the same selection
painting. If desktop selection fails with Lively Wallpaper running, compare
native selection with this mod disabled. Closing Lively restored native
selection in the original test environment; this is not a universal diagnosis.

## Install through Windhawk

1. Install [Windhawk](https://windhawk.net/).
2. Choose **Create a New Mod**.
3. Replace all of the editor's mod.wh.cpp with
   [rounded-desktop-selection.wh.cpp](rounded-desktop-selection.wh.cpp).
4. Compile and enable from the Windhawk sidebar.
5. Adjust Settings and test desktop and Explorer selection.

This repository is a standalone project, not an official Windhawk collection entry.

## Build and install with PowerShell

Requires Windows x64, PowerShell 5.1 or 7, and the Windhawk compiler.

```powershell
.\scripts\check-project.ps1
.\build.ps1
.\build.ps1 -Test
```

Paths are discovered from windhawk.ini. The ID and version come from C++ metadata.
Builds, runtimes and generated previews go to the ignored build directory.

In an **elevated PowerShell session**:

```powershell
.\install.ps1
# For an existing local installation:
.\update.ps1
```

Updating preserves existing settings and enabled state, adding new settings at
their defaults. An interrupted update leaves the mod disabled. Portable Windhawk
users should use its editor instead of these direct installation scripts.

To manage the installed mod, use Windhawk or elevated PowerShell:

```powershell
.\disable.ps1
.\enable.ps1
```

## Checks and limitations

The renderer suite covers 38 checks: alpha blending, transparency preservation,
rounded geometry, dirty-region clipping, theme-state routing and GDI resource
cleanup. Live testing remains necessary for Windows hooks and visual integration.

Desktop 0.1.2 was manually validated without trails. Explorer marquee, header
and view-button styling were also verified visually. In 0.2.4, the user confirmed
that the unwanted black file-row rectangle was removed. These results apply to
the initial environment. In 0.2.6, the held-click overlay was also visually
confirmed to retain the rounded translucent style without blue/black artifacts.
Each supported Windows build still needs live testing.
